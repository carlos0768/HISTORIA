# 07. 教材生成パイプラインとプロンプト設計

> 対象: HISTORIA MVP / 状態: 確定（v0.3 で生成方式を変更） / 最終更新: 2026-09-01
>
> **v0.2 からの変更**: 共有カタログ方式を廃止し、教材と設問を**ユーザーごとに生成**する方針に変更した。
> あわせてモデルを Gemini API の無料枠に変更した（`08-ai-architecture.md` §1）。

## 0. この文書が解く問題

v0.1 は「**教材は死ぬほどこだわるべき**」「**かなり長文にする。そうじゃないと、単なる暗記アプリ**」
と書いているが、中身の定義がゼロだった。さらに次の2点が危険である。

1. **「長文＝深い学習」は学習科学の知見と逆行する。** Dunlosky et al. (2013) の10手法レビューでは、
   再読（rereading）・要約・ハイライトは utility 低、**練習テスト（practice testing）と
   分散学習（distributed practice）が utility 高**と評価されている。長文を読ませる設計は
   学習行動としては再読に近く、投資（生成コスト＋読解時間）に対する効果が最も低い象限に資源を集中させる
2. **「6行」は仕様にならない。** 行はデバイス幅で変わる。スマホ幅の6行とPC幅の6行では文字数が2〜3倍違う

**長文であることは手段であって目的ではない。** 目的は「暗記の羅列にしないこと」であり、
それは**分量ではなく構造（因果・比較・ヨコの視点）**で達成する。

## 1. 「良い世界史教材」の定義

対象は共通テスト＋私大マーク（`01-product.md`）。この層に効く教材は次の条件を満たす。

| # | 条件 | 理由 |
|---|---|---|
| C1 | 冒頭に「この単元で答えられるようになる問い」を3〜5個置く | 事前質問は後続の読解の定着を上げる。読む目的が明確になる |
| C2 | 因果を矢印で明示する（「Aが起きた → だからBになった」） | 共通テストは因果の理解を問う。羅列では点にならない |
| C3 | **ヨコ（同時代の他地域）の視点を必ず1節入れる** | 受験世界史で最も差がつく。タテだけの教材は他アプリと同じ |
| C4 | よくある誤解（混同されやすい対）を明示的に扱う | `kind=distinction` のKCに直結する。`misconception` の解消 |
| C5 | 本文中の重要語を KC に紐づけて宣言する | 弱点DB・確認テスト・動画と接続するための必須情報 |
| C6 | 末尾に「本文を隠して答える問い」を置く | retrieval practice を教材内に埋め込む |
| C7 | 分量は**文字数**で規定する（行数ではない） | 生成の制御とコスト見積りのため |

## 2. 教材の構造テンプレート（確定）

1教材 = 1 `syllabus_unit`（教科書の節）に対応する。

| § | セクション | 文字数 | 必須 |
|---|---|---|---|
| 1 | この単元で答えられるようになること（問い3〜5個） | 150〜250 | ○ |
| 2 | 全体の見取り図（時系列または因果の骨格を箇条書き） | 200〜350 | ○ |
| 3 | 本文（因果連鎖を明示した叙述。2〜4個の小見出しに分ける） | 1,600〜2,200 | ○ |
| 4 | 同時代の他地域では何が起きていたか（ヨコの視点） | 400〜600 | ○ |
| 5 | よくある誤解（混同されやすい対を2〜4組） | 300〜500 | ○ |
| 6 | ここだけは押さえる（要点10項目以内） | 200〜300 | ○ |
| 7 | 自己テスト（本文を隠して答える問い5問。解答は折りたたみ） | 200〜300 | ○ |
| | **合計** | **3,050〜4,600字**（目標 3,500字 ±15%） | |

スマホでの読了時間は日本語の黙読速度を毎分500字として **約7分**。
セクション単位で進捗を保存し、中断・再開できるようにする（`11-ux.md`）。

## 3. 生成方式 — ユーザーごとに1回生成する

v0.1 の「**内容はユーザの苦手範囲に基づいて生成**」は、
「全ユーザーで使い回す」とも「ユーザーごとに生成する」とも読めた。

**決定（作者判断）: 教材も設問も、ユーザーごとに生成する。**

### 3.1 「毎回」の定義

**「毎回」＝「そのユーザーがその範囲を初めて開いたときに1回」であって、
「開くたびに作り直す」ではない。**

```
生成の単位:  (user_id, syllabus_unit.id)
生成の契機:  そのユーザーがその unit を初めて必要とした時点
保存:        material / item に user_id を持たせて永続化する
再生成:      ユーザーが明示的に「作り直す」を押したときのみ
```

#### 3.1.1 初回教材は共有する（2026-09-02 追記）

**実装してみて分かったこと: 初回教材はユーザーごとに作っても中身が同じになる。**

`buildGenerationContext` が個別化に使うのは `p_know`（帯）と `misconception` だけである。
初回はどちらも空なので、帯は全て既定値、混同情報は無し、KC の並びは
`exam_weight` だけで決まる。**誰に対しても同じプロンプトが組み立つ。**

つまり10人ぶん作れば、同じものを10回作って生成費を10倍払うことになる。
生成が課金対象になった以上（`14` M28）、これは無視できない。

```
material.user_id IS NULL  = 共有教材。誰の弱点にも寄せていない初回版
material.user_id 非NULL   = 個別教材。弱点が溜まった利用者に作り直したもの
```

- 生成前に共有教材の有無を見る。あれば**生成しない**（費用ゼロ）
- 文脈が既定のまま（`isDefaultContext`）なら、結果を共有として保存する
- 弱点が溜まった利用者には個別に作り直す。共有版はそのまま残る
- **設問だけは利用者ごとに複製する。** `item.user_id IS NULL` は
  「診断用の共有プール」を意味し、Elo の較正はそこでのみ行われる（`04b`）。
  生成物を混ぜると較正の前提が壊れる。複製は SQL だけで済み、API を呼ばない

10人 × 75節なら **750回 → 75回**。個別最適化は2回目以降に効くので何も失わない。

開くたびに作り直すと次が壊れる。

| 壊れるもの | 理由 |
|---|---|
| 読了進捗 | セクション構成が変わるので `material_read` の対応が切れる |
| 「教材 §3 に戻る」導線 | 確認テストで落とした KC に対応するセクションが消える |
| leech からの復帰 | 読み直すべき教材が別物になる（`04b` §7） |
| RPD の消費 | 無料枠のリクエスト数が数倍になる（`08-ai-architecture.md` §3） |

### 3.2 設問も毎回生成することの帰結

**設問を毎回生成すると、SM-2 を item 単位で回せなくなる。**
`card (user_id, item_id)` は同じ item が繰り返し出題されることを前提にしているためである。

したがって **SM-2 の適用単位を KC に移した**（`04b-spaced-repetition.md` §1.2）。
この変更には利点と代償の両方がある。

| | 内容 |
|---|---|
| 利点 | 同じ知識が毎回違う切り口で問われ、問題文の丸暗記で正解できなくなる。**入試の初見問題への転移が良くなる** |
| 利点 | 教材とは別の設問で問うため、§0 で懸念した「逐語再認」の問題が構造的に消える |
| 代償 | **Elo による難易度較正が効かない**。同じ item が二度と出ないため観測が溜まらない |
| 代償 | 生成量に比例してリクエストが増える |

### 3.3 失うもの — 人手レビュー

**これが最大の代償である。**

共有カタログ方式では、教材400本を作者が人手でレビューしてから配信できた。
1件の修正が全ユーザーに効き、レビュー対象は有限だった。

ユーザーごと生成では、**生成量がレビュー容量を無限に超えるため人手レビューが不可能になる**。
世界史は年号・人名・因果が命であり、受験生は誤りを検知できない読者である。

**代わりの防衛線は機械照合しかない**（`08-ai-architecture.md` §5）。

- 正典マスタ `canon_event` を **1,500件 → 3,000件**に増やす
- 照合で FLAG が出た段落は**再生成し、3回目も駄目なら表示しない**（層5）
- ユーザー報告（層4）を最後の砦とし、報告された事実を `canon_event` に追加して層2を育てる

**「誤っているかもしれない記述を、検証できないまま受験生に見せない」**を原則とする。
共有カタログなら人手で直せたが、いまは「出さない」しか選択肢がない。

### 3.4 生成量とリクエスト数

| 項目 | 値 |
|---|---|
| 1ユニットの生成 | 1リクエスト（教材＋FC＋四択＋`claims` を構造化出力で同時に） |
| ファクトチェック照合 | 1リクエスト |
| 設問プールの補充（`items_refresh`） | 1リクエスト。KC のプールが尽きたときのみ（`04b` §5） |
| 10人 × 3特訓並行 | 約60リクエスト/日（無料枠 1,500 RPD の **4%**） |

**個人差分（`material_personalization`）は廃止する。** 教材本文そのものが
そのユーザー向けに生成されるため、別立ての差分が不要になった。

### 3.5 設問プールの蓄積

設問は使い捨てではなく `(user_id, kc_id)` ごとに蓄積する。

```
1 KC あたりの上限:      12 問
再出題の禁止期間:        14 日
プールが尽きたとき:      items_refresh を1回キューに入れ、今回は最も古い問題を出す
```

これで復習のたびに生成が走ることを防ぎ、RPD の消費を抑える。

## 4. 2フェーズ生成 — 分割を AI に丸投げしない

v0.1 は「**範囲からどれくらいの単位に分けて文章を作るかも完全にAIに決めさせる**」としていたが、
これをそのまま実装すると

- 同じ「フランス革命〜ナポレオン」が今日は4単位、明日の再生成では7単位になる
- 「一日にこなすべき量」の逆算の**分母が非決定的**になる
- 1ユニットの生成に必要なリクエスト数が予測できず、無料枠の RPD 消費が読めない
- 再生成すると別の分割になるため既存の進捗とマッピングできず、**再生成＝進捗リセット**になる

**決定: 分割は AI に決めさせない。`syllabus_unit`（教科書の節）を単位とする**
（`02-domain-model.md` §4.4）。生成は次の2フェーズに分ける。

```
Phase 1: 範囲 → syllabus_unit の集合  … DBの引き当てのみ。LLM を使わない
Phase 2: unit ごとに独立ジョブで本文＋item を生成  … 1 unit = 1 ジョブ
```

Phase 1 に LLM が不要なのは、範囲指定を `syllabus_unit` の選択UIで受けるからである
（`11-ux.md`）。自然文で範囲を指定する導線（§8）でも、LLM の役割は
「**既存の unit ID を選ぶ**」ことに限定し、新しい分割を作らせない。

## 5. プロンプト（v1）

以下をそのまま実装に使う。`{{...}}` は差し込み変数。
プロンプトは `prompts/material_v1.md` としてリポジトリで版管理し、
`material.prompt_version` に `material_v1` を記録する。

### 5.1 システムプロンプト

```text
あなたは日本の大学受験生向けに世界史・歴史総合の学習教材を書く専門家です。
対象読者は共通テストおよび私立大学のマーク式入試を受ける高校生です。

# 絶対に守ること
1. 事実の正確性を最優先する。年号・人名・地名・因果関係に誤りがあってはならない。
   確信が持てない事実は書かない。曖昧な記憶に頼るより、書かない方が良い。
2. 事実を羅列しない。必ず「なぜそうなったか」「その結果どうなったか」で繋ぐ。
3. 読者は初学者ではなく、教科書を一度は読んでいる受験生である。
   用語の定義から始めるのではなく、つながりと区別を与えることに集中する。
4. 出力は指定された JSON スキーマに厳密に従う。スキーマ外のキーを足さない。
5. 本文中で扱った知識項目は、与えられた候補KCリストの id からのみ選ぶ。
   リストに無い項目を新しく作ってはならない。
6. 教育目的の教材であるため、戦争・虐殺・宗教対立・植民地支配などの主題を
   歴史的事実として中立に記述する。事実の記述を避けたり婉曲にしたりしない。

# 文体
- です・ます調。
- 1文は60字以内を目安にする。スマートフォンで読まれる。
- 専門用語には初出時に短い補足を括弧で付ける。
- 「〜と言われている」「〜かもしれない」のような曖昧表現を使わない。
  諸説ある場合は「A説とB説がある」と明示する。
```

### 5.2 ユーザープロンプト

```text
# 生成対象
教科書の単元: {{syllabus_unit.label}}（{{syllabus_unit.subject}}）
上位単元: {{parent_unit_labels}}
時代: {{era.label}}（{{year_from}}〜{{year_to}}）
主な地域: {{region_labels}}

# この単元で扱う知識項目（候補KC）
以下の id からのみ選んでください。すべてを使う必要はありませんが、
exam_weight が高いものは優先してください。
{{#each candidate_kcs}}
- {{id}} | {{kind}} | {{label}} | exam_weight={{exam_weight}}
{{/each}}

# 出力するもの
1. 教材本文（7つのセクション。構成と文字数は下記のとおり）
2. その教材から作るフラッシュカード 10〜14枚
3. その教材から作る四択問題 6〜10問

# 教材本文の構成（各セクションの文字数を守ること）
§1 この単元で答えられるようになること … 問いを3〜5個。150〜250字
§2 全体の見取り図 … 時系列または因果の骨格を箇条書き。200〜350字
§3 本文 … 2〜4個の小見出しに分ける。因果を「→」で明示する。1,600〜2,200字
§4 同時代の他地域では何が起きていたか … 400〜600字。★必須。省略禁止
§5 よくある誤解 … 混同されやすい対を2〜4組。「AとBの違い」の形で。300〜500字
§6 ここだけは押さえる … 10項目以内の箇条書き。200〜300字
§7 自己テスト … 本文を隠して答える問いを5問（解答付き）。200〜300字

合計 3,050〜4,500字。目標 3,500字。

# セクションとKCの対応
各セクションについて、そこで扱ったKCの id を列挙してください。
§4（ヨコの視点）は kind=chronology のKCに紐づくことが多いはずです。

# 四択問題の作り方（最重要）
誤答の選択肢（distractor）の質が学習効果を決めます。以下を守ってください。

【良い distractor】
- 同時代・同地域の別の人物／王朝／条約（例: 正解がウマイヤ朝なら、誤答にアッバース朝）
- 1つだけ要素がずれている記述（年号だけ違う、主体だけ違う、結果だけ違う）
- 受験生が実際に混同しやすい対（§5 で扱った誤解をそのまま使う）
- 「もっともらしいが史実と食い違う因果」

【悪い distractor（禁止）】
- 時代も地域も全く違うもの（消去法で瞬時に切れる）
- 明らかに荒唐無稽なもの
- 選択肢の文字数が正解だけ極端に長い／短いもの
- 「すべて正しい」「いずれでもない」

各誤答について、なぜそれが誤りなのかの説明を必ず付けてください。
その説明は、その誤答を選んだ生徒にそのまま提示されます。

# フラッシュカードの作り方
- 表は問い、裏は答え。答えは30字以内。
- 「〜について説明せよ」のような自己採点できない問いを作らない。
- 1枚1項目。複数の事実を1枚に詰めない。

# 検証用の主張リスト（claims）
**あなたが書いた本文から、事実として検証できる主張を 12〜24 件抜き出してください。**
このリストは別の検証者が1件ずつ事実確認するために使います。
ここに挙げなかった主張は誰にも検証されないまま読者に届きます。

（kind の一覧と書き方の規則は prompts/material_v2.md を参照）
```

**この節は v1 に存在しなかった。** その結果 `claims` を指示しないまま出力させており、
モデルが空配列を返すと層2は照合対象0件、層3は呼ばれず、
`wrong` が空のまま `status = 'ready'` になっていた。
**5層防御が沈黙のうちに0層になる経路**である（実装で確認済み）。
`material_v2` で指示を追加し、スキーマに `minItems` を入れ、
パイプラインにも「claims が空なら配信しない」を置いた。

### 5.3 構造化出力スキーマ

Gemini API の構造化出力（`responseMimeType: 'application/json'` ＋ `responseSchema`）で強制する。
`required` を全階層に付ける。

**要検証**: Gemini の `responseSchema` は JSON Schema のサブセットであり、
`additionalProperties` や深いネストの扱いが Anthropic と異なる可能性がある。
下記スキーマがそのまま通るかを実装前に確認し、通らなければ階層を浅くする
（`08-ai-architecture.md` §10-7）。

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["title", "sections", "flashcards", "mcqs", "claims"],
  "properties": {
    "title": { "type": "string", "maxLength": 60 },
    "sections": {
      "type": "array", "minItems": 7, "maxItems": 7,
      "items": {
        "type": "object", "additionalProperties": false,
        "required": ["ord", "heading", "body_md", "kc_ids"],
        "properties": {
          "ord":     { "type": "integer", "minimum": 1, "maximum": 7 },
          "heading": { "type": "string" },
          "body_md": { "type": "string" },
          "kc_ids":  { "type": "array", "items": { "type": "string" } }
        }
      }
    },
    "flashcards": {
      "type": "array", "minItems": 10, "maxItems": 14,
      "items": {
        "type": "object", "additionalProperties": false,
        "required": ["front", "back", "kc_ids"],
        "properties": {
          "front":  { "type": "string" },
          "back":   { "type": "string", "maxLength": 30 },
          "kc_ids": { "type": "array", "minItems": 1, "items": { "type": "string" } }
        }
      }
    },
    "mcqs": {
      "type": "array", "minItems": 6, "maxItems": 10,
      "items": {
        "type": "object", "additionalProperties": false,
        "required": ["stem", "choices", "answer_key", "explanation", "kc_ids"],
        "properties": {
          "stem": { "type": "string" },
          "choices": {
            "type": "array", "minItems": 4, "maxItems": 4,
            "items": {
              "type": "object", "additionalProperties": false,
              "required": ["key", "text", "why_wrong"],
              "properties": {
                "key":       { "type": "string", "enum": ["a", "b", "c", "d"] },
                "text":      { "type": "string" },
                "why_wrong": { "type": "string", "description": "正答の場合は空文字" }
              }
            }
          },
          "answer_key":  { "type": "string", "enum": ["a", "b", "c", "d"] },
          "explanation": { "type": "string" },
          "kc_ids":      { "type": "array", "minItems": 1, "items": { "type": "string" } }
        }
      }
    },
    "claims": {
      "description": "本文中の検証可能な主張。ファクトチェックに使う（08-ai-architecture.md §5）",
      "type": "array",
      "minItems": 6,
      "maxItems": 40,
      "items": {
        "type": "object", "additionalProperties": false,
        "required": ["kind", "text", "section_ord"],
        "properties": {
          "kind":        { "type": "string", "enum": ["year", "person", "event", "causal", "place"] },
          "text":        { "type": "string" },
          "subject":     { "type": "string" },
          "year_from":   { "type": "integer" },
          "year_to":     { "type": "integer" },
          "section_ord": { "type": "integer" }
        }
      }
    }
  }
}
```

**教材・フラッシュカード・四択を1回の生成パスで同時に出す**ことが重要である。
別々に生成すると内容がズレ（教材で扱っていない項目が四択に出る）、
`06-assessment.md` §3.3 の「教材にない知識を問わない保証」が崩れる。

`claims` を同時に出させることで、ファクトチェックのために本文を再度 LLM に読ませる必要がなくなる。

### 5.4 弱点情報の渡し方（個人差分プロンプトは廃止）

v0.2 では共有カタログ本文に対して「あなた向けのポイント」を別途生成していたが、
**教材本文そのものがそのユーザー向けに生成される**ため、個人差分は廃止した。

代わりに、§5.2 のユーザープロンプトに**弱点情報を直接埋め込む**。
`08-ai-architecture.md` §4.1 の匿名化規則に従い、**個人識別情報と生の数値を送らない**。

```text
# この学習者の状況（識別情報は含まれません）
{{#each target_kcs}}
- {{id}} | 習得度: {{level}}          ← level は 'low' / 'mid' / 'high' の3段階のみ
{{#if misconception}}  混同: 「{{misconception_label}}」を繰り返し選んでいる{{/if}}
{{/each}}

# 指示
習得度 low の項目は §3 本文と §5「よくある誤解」で厚く扱ってください。
混同が記録されている対は、§5 で必ず1組として取り上げてください。
習得度 high の項目は簡潔に触れるにとどめ、分量を low の項目に回してください。
四択の難易度は、習得度 low の項目については基礎的な事実確認から入るものにしてください。
```

**送ってよいのは KC の id・3段階の習得度・誤選択肢のラベル（歴史用語）だけである。**
`user_id`・氏名・生年月日・生の正答率・解答時刻・行動ログは一切渡さない。
この制約は型で強制する（`08-ai-architecture.md` §4.2）。

## 6. 品質評価 — LLM-as-judge ルーブリック

プロンプトの改善は「なんとなく良くなった」では回らない。**採点基準を先に固定する。**

代表20単元を固定のベンチマークセットとし、プロンプトを変更するたびに全20件を再生成して採点する。

| 軸 | 1点 | 3点 | 5点 |
|---|---|---|---|
| **事実正確性** | 年号・人名の誤りが3件以上 | 誤りが1件（軽微） | 誤りなし。年代・主体・因果すべて教科書と整合 |
| **因果の明示** | 事実の羅列。「→」がほぼ無い | 主要な因果は書かれているが一部が飛んでいる | すべての主要事象が原因と結果で接続されている |
| **ヨコの視点** | §4 が無い、または他地域名の列挙のみ | 他地域の出来事は書かれているが関連が薄い | 同時代の他地域と本題が明確に関連づけられている |
| **誤解への対処** | §5 が無い、または一般論 | 混同されやすい対が挙がっている | 対ごとに「何が違うか」が1文で言い切られている |
| **受験適合** | 教科書範囲外の細部に偏る／逆に浅すぎる | 概ね範囲内 | 共通テスト・私大マークの頻出項目を過不足なく覆う |
| **読みやすさ** | 1文が長く、スマホで読めない | 概ね読める | 1文60字以内、小見出しで構造化されている |
| **distractor の質** | 消去法で瞬時に切れる誤答が半数以上 | 一部が易しすぎる | すべて同時代・同種で、混同しやすい |

```
判定:
  全軸 4点以上          → 採用（approved）
  事実正確性が 3点以下  → 無条件で再生成（他の軸が満点でも不可）
  合計 28点未満（/35）  → 再生成
  再生成は同一単元につき最大2回。3回目も基準未達なら人手レビューキューへ
```

**採点は生成に使ったのとは別系統の課金モデルで行う**（`08-ai-architecture.md` §2）。
生成が Gemini Flash 系（無料枠）、採点が Claude Sonnet 5（課金）である。
自己採点は甘くなるため、訓練系統の違うモデルを当てる。

judge の単価は 4.5円/回（入力12,000・出力600トークン）。
A/Bテスト1回（20単元 × 2版 = 40件）で **約180円**。

### 6.1 judge を回すのは開発時だけ

利用者ごとに生成される教材を毎回 judge にかけると、リクエスト数が倍になる。

```
開発時（プロンプト改善）: ベンチマーク20単元に対して judge を回す（約180円/回）
実行時（ユーザーの生成）: judge を回さない。§5 のファクトチェック（層2・層3）のみ
```

事実正確性は judge ではなく `canon_event` との機械照合（層2）と
**別系統の課金モデルによる二次照合（層3）** で担保する。
judge は**文章の質**を測る道具であり、事実の検証器としては使わない。

### 6.1.1 judge でしか測れないもの

機械照合が守るのは事実だけである。次の2つは照合では検出できず、judge にしか測れない。

- **誤答選択肢(distractor)の質** — 「消去法で瞬時に切れる選択肢」は事実としては正しい。
  しかし学習効果を直接損なう
- **因果の説明の質** — 個々の事実が正しくても「AだからB」の論理が雑なことはある

**Flash 系が上位モデルに劣るとしたら、事実より先にここで劣る可能性が高い。**
Phase 0 では誤り件数と一緒に judge も必ず回すこと。

### 6.2 プロンプトのA/Bテスト手順

```
1. prompts/material_v{N}.md を作る（v1 からの変更点を先頭にコメントで書く）
2. ベンチマーク20単元を v{N-1} と v{N} の両方で生成する（無料枠の RPD を80消費、judge の課金が約180円）
3. 同じ judge プロンプトで両方を採点する
4. 軸ごとの平均点を比較する。合計点が上がっても事実正確性が下がったら採用しない
5. 採用したら prompt_version を上げ、既存教材の再生成は §7 の方針に従う
```

## 7. 版管理と再生成

```sql
-- material テーブル（抜粋。全体は 03-data-model.md）
prompt_version  text NOT NULL,     -- 'material_v1'
model           text NOT NULL,     -- 'gemini-flash'（08-ai-architecture.md §2）
generated_at    timestamptz NOT NULL,
supersedes_id   uuid REFERENCES material(id),
status          text NOT NULL CHECK (status IN ('draft','approved','superseded','flagged'))
```

**プロンプトを改善しても、既存の教材を自動で差し替えない。**

理由: `material_section` は `material_section_kc` を通じて KC と結び付いており、
「間違えた項目の教材に戻る」導線（`04b-spaced-repetition.md` §7）がそこにぶら下がっている。
教材を差し替えるとセクション構成が変わり、この導線と読了進捗が切れる。

**決定: 既存の教材はそのまま残す。新しいプロンプトは、これから生成される教材にのみ適用する。**
ユーザーごと生成では「全員の教材を作り直す」という操作自体が存在しない（生成量が読めないため）。
ユーザーが明示的に「作り直す」を押した場合のみ、最新の `prompt_version` で再生成し、
旧版を `superseded` にして `supersedes_id` で辿れるようにする。

再生成しても **`kc_card` と `user_kc_state` は KC 単位なので影響を受けない**。
これが `04-weakness-engine.md` §4 で KC 層を教材から独立させた設計の効果である。

`status` の値は毎回生成に合わせて次の意味になる。

| `status` | 意味 |
|---|---|
| `generating` | 生成中（ジョブがキューまたは実行中） |
| `ready` | 事実確認を通過し、ユーザーに表示できる |
| **`blocked`** | **事実確認を通らなかったため配信しない**（`08` §5 層5）。`blocked_reason` に検出内容を記録 |
| `superseded` | ユーザーが作り直したため置き換えられた |
| `failed` | 生成に失敗した（モデルの拒否・タイムアウト等） |

**部分配信をしない（作者の決定）。** 一部のセクションだけ落として残りを表示すると、
因果の連鎖が途切れた文章を受験生が読むことになる。誤りが残るなら**ユニットごと出さない**。

## 8. 範囲指定の2ルート

v0.1 は「**簡単なプロンプトで指定することもできるし、具体的に特定することもできる。
前者の場合は、確定する前にAIに確認させる**」としていた。

### 8.1 ルートA: 章立てから選ぶ（既定）

`syllabus_unit` のツリーをチェックボックスで選ぶ。LLM を使わない。確実で、コストゼロ。

### 8.2 ルートB: 自然文で指定する

```
ユーザー入力: 「ルネサンスから宗教改革あたりが不安」
    ↓
LLM に unit 候補を選ばせる（構造化出力・既存 unit ID からのみ選択）
    ↓
確認画面（★必須）:
  「次の範囲でよろしいですか？」
   ☑ 第2部 第4章 第1節 ルネサンス
   ☑ 第2部 第4章 第2節 宗教改革
   ☑ 第2部 第4章 第3節 主権国家体制の形成   ← ユーザーが外せる
   [ 章立てから選び直す ]  [ この範囲で作る ]
    ↓
確定した unit 集合を drill_kc に保存
```

**LLM の出力をそのまま確定しない。** これが v0.1 の「確定する前にAIに確認させる」の実装である。
ただし「AIに確認させる」のではなく「**AIの提案をユーザーに確認させる**」に読み替える。
LLM に自分の出力を検証させても精度は上がらない。

出力スキーマ:
```json
{
  "type": "object", "additionalProperties": false,
  "required": ["unit_ids", "interpretation"],
  "properties": {
    "unit_ids":       { "type": "array", "minItems": 1, "maxItems": 12,
                        "items": { "type": "string" } },
    "interpretation": { "type": "string", "description": "どう解釈したかの一文" }
  }
}
```

`unit_ids` は `syllabus_unit.id` の外部キーで DB 層でも検証される。

## 9. 自学モード（`mode = 'self_study'`）

v0.1 は「教材はAIが生成する、もしくはユーザが自学するかの二つを選ぶことができる」としていたが、
自学を選んだ場合に確認テストの出題根拠が何になるのかが未定義だった。

**決定: 自学モードでも `item` は生成する。教材本文だけを生成しない。**

```
mode='ai_material' : 教材本文 §1〜§7 ＋ flashcards ＋ mcqs を生成
mode='self_study'  : flashcards ＋ mcqs のみ生成（§5.2 のプロンプトから本文の指示を外す）
```

`item` が無いと確認テストもフラッシュカードも出せず、弱点DBに何も溜まらない。
自学モードは「**教科書で読む。問題演習と進捗管理だけアプリでやる**」というユースケースであり、
これは受験生にとって十分に自然な使い方である。

自学モードは本文を生成しない分、出力トークンが約6割になる。リクエスト数は同じ1件である（`08-ai-architecture.md` §3）。

## 10. Wiki リンクは MVP では張らない

v0.1 は「重要な単語にはリンクを設定し、実際にWikipediaのページに飛ばせるようにする。
それか世界史専用の学習用ページでもいい。**両方実装しておく**」としていた。

**決定: MVP では教材本文にリンクを一切張らない。** Phase2 に回す。

理由:
- 「重要な単語」の判定基準が無い。用語マスタ（正規語・別表記・頻度）が存在しない状態で
  AI生成本文の語をそのまま Wikipedia 記事名に投げると、
  「フビライ／クビライ」「ムハンマド／マホメット」「ティムール朝／ティムール帝国」等の表記ゆれで
  **誤リンクが記事数に比例して蓄積し、後から手作業で直せない規模になる**
- Wikipedia は受験の到達範囲を意識せず書かれているため、飛んだ先で不要な情報を大量に読むことになり、
  §0 の再読問題を悪化させる
- 「世界史専用の学習用ページ」を自前で持つのは、実質的に用語集相当のコンテンツ
  （数千語 × 解説）を自作するという意味であり、個人開発の工数として過小評価されている

**MVP における教材からの外部導線は YouTube 動画のみとする**（`09b-video.md`）。
Phase2 の用語マスタ設計は `09-content-sourcing.md` §4 に記載する。

## 11. 生成教材に Wikipedia 本文を渡さない

プロンプトのコンテキストに Wikipedia 本文を投入しない。
日本語版 Wikipedia は CC BY-SA 4.0 であり、その表現が実質的に残った生成物は
**継承（同一ライセンスでの頒布）義務の対象になりうる**。
利用規約に「本サービスのコンテンツの著作権は運営者に帰属し、複製・再配布を禁じる」と書いた瞬間に
ライセンス違反になる（`10-legal-risk.md` §5）。

```sql
material.source = 'ai_generated_no_external_text'   -- 全教材で固定
```

grounding は Wikipedia ではなく、**自前の正典マスタ（`event` / `person`）との機械照合**で行う
（`08-ai-architecture.md` §5）。
