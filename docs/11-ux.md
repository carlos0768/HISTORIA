# 11. UX・情報設計

> 対象: HISTORIA MVP / 状態: 確定 / 最終更新: 2026-09-01

## 0. 「UIは機能完成後」という方針について

v0.1 は「**シンプルかつクールなのにしたい。しかし、UIにこだわるのは機能面が完成した後にする**」と書いている。

**見た目（配色・タイポグラフィ・余白）を後回しにするのは正しい。**
一方で**情報設計（何を、どの順で、どの画面に出すか）は後回しにできない**。
ホームに何を出すかはスケジューラの出力仕様を決め、教材ビューアの進捗保存はスキーマを決めるからである。

本文書は**情報設計を確定し、見た目は方針だけを決める**。

## 1. ホーム画面 — v0.1 の設計を変更する

### 1.1 v0.1 の問題

v0.1 のホームは「**『あと⚪︎日 で〜を仕上げよう！！』のボタンが並んでる感じ**」で、
押すと分野ごとの仕分けがあり、さらに押すと教材が入っている。

| 問題 | 具体的に何が起きるか |
|---|---|
| **空状態の設計が皆無** | 新規ユーザーは特訓0件なので、初回起動でホームが真っ白になる |
| 特訓が多いと破綻する | 5本並べると画面が埋まり、優先順位が分からない |
| **今日やることが分からない** | 「あと12日」は状態であって行動ではない。押してから2階層潜らないと学習が始まらない |
| 3階層タップが深い | ホーム → 分野 → 教材。毎日の学習でこれを繰り返す |

### 1.2 決定: ホームは「今日やること」を出す

```
┌──────────────────────────────────┐
│  HISTORIA                    12日連続 │
├──────────────────────────────────┤
│                                          │
│   今日やること                            │
│   ┌────────────────────────────┐  │
│   │        42 問                        │  │
│   │   ████████░░░░░░░  18/42 完了       │  │
│   │                                     │  │
│   │      [ 今日の学習を始める ]  ←1タップ │  │
│   └────────────────────────────┘  │
│                                          │
│   進行中の集中特訓                        │
│   ┌────────────────────────────┐  │
│   │ イスラーム世界の形成                 │  │
│   │ あと 12日   習得 18/48 KC (38%)     │  │
│   │ 読了 ████████░░ 8/12                │  │
│   └────────────────────────────┘  │
│   ┌────────────────────────────┐  │
│   │ 近代ヨーロッパ            要調整  │  │
│   │ あと 6日    習得 5/62 KC (8%)       │  │
│   │ このペースでは間に合いません          │  │
│   └────────────────────────────┘  │
│                                          │
│              [ + 新しい集中特訓 ]         │
└──────────────────────────────────┘
```

**「今日やること」を1つの数字にする。** 特訓ごとのノルマは出さない
（合計が一致せず混乱するため。`05-scheduler.md` §5.1）。
特訓カードには**残日数と進捗率のみ**を出す。v0.1 の「あと⚪︎日で〜を仕上げよう」は
この特訓カードとして残る。

**1タップで学習が始まる。** ホーム → 出題。教材を読むかカードをやるかはキューが決める。

### 1.3 「要調整」バッジ

`daily_plan().feasible = false` の特訓には警告を出す（`05-scheduler.md` §3.2）。
タップすると調整画面（締切延長／範囲削減／このまま続ける）へ遷移する。

**黙って上限で丸めない。** 「毎日ノルマを達成しているのに締切に間に合わない」は最悪の体験である。

## 2. 空状態の設計

**空状態は例外ではなく、全ユーザーが必ず最初に見る画面である。**

| 状況 | 表示 |
|---|---|
| **サインアップ直後（診断前）** | 「まず10分の診断テストで、今の状態を測ります」＋ [ 診断を始める ]。他の導線を出さない |
| **診断後・特訓0件** | 診断で θ が低かった上位3セルを提示し、「この範囲から始めますか？」＋ [ 集中特訓を作る ]。加えて「今日やること」に診断で弱かったKCの復習キューを出す（**空にしない**） |
| **特訓はあるが今日のキューが空** | 「今日の分は終わりました」＋ 明日の予定件数＋ [ 先取りする ]（明日以降の due を前倒し） |
| **全KCが `mastered`** | 「この範囲は仕上がっています」＋ 保持のための復習のみ |
| **教材の生成待ち**（v0.3 で MVP に昇格） | §2.1 |
| **通信エラー** | 直前の状態を保持し「接続できません。再試行」。入力中の解答を失わない |

### 2.1 教材の生成待ち（v0.3 で追加）

**毎回生成にしたため、特訓を作った直後の1本目だけは 2〜3分待つことになる**
（`08-ai-architecture.md` §8.3）。2本目以降は先読み生成されるので待ちは発生しない。

```
┌──────────────────────────────┐
│ ← 戻る   イスラーム世界の形成        │
├──────────────────────────────┤
│                                      │
│   教材を作っています                  │
│                                      │
│   ▓▓▓▓▓▓▓▓░░░░░░░  およそ2分         │
│                                      │
│   ✓ 本文を書いています                │
│   ・ 設問を作っています                │
│   ・ 年号と人名を照合しています         │
│                                      │
│   [ できたら知らせる ]                │
│   画面を閉じても生成は続きます          │
└──────────────────────────────┘
```

- **段階を出す。** 単なるスピナーにしない。何が起きているか分かると待てる
- **画面を離れられるようにする。** 「できたら知らせる」で通知を予約し、他のことをできるようにする
- 生成中も**既に生成済みの他の範囲は学習できる**。ホームに戻れば今日のキューが出る
### 2.2 教材が配信できなかったとき（v0.3・Q4 の決定）

事実確認を通らなかった教材は**配信しない**（`08-ai-architecture.md` §5 層5）。
モデルが単元を拒否した場合（同 §9）も同じ画面に落とす。

```
┌──────────────────────────────┐
│ ← 戻る   イスラーム世界の形成        │
├──────────────────────────────┤
│                                      │
│   この単元の教材は作れませんでした      │
│                                      │
│   内容の確認が取れなかったため、         │
│   誤った説明をお見せしないよう          │
│   表示を止めています。                 │
│                                      │
│   [ 問題演習だけ始める ]  ← 設問は出せる │
│   [ もう一度作ってみる ]  ← 1日1回まで  │
│                                      │
│   教科書の該当範囲: 第2部 第4章 第1節   │
└──────────────────────────────┘
```

**「エラーが起きました」で終わらせない。** 3つを必ず出す。

1. **なぜ止めたのか**（誤った説明を見せないため）— 不具合ではなく意図した動作だと伝える
2. **いま何ができるか**（問題演習は動く）— 学習を止めない
3. **教科書のどこを読めばいいか**（`syllabus_unit` のラベル）— 代替手段を渡す

再試行は1日1回までとする。無料枠の RPD を消費するためと、
同じプロンプトで何度試しても結果が変わらない可能性が高いためである。

```
┌──────────────────────────────────┐
│ ← 終了              18 / 42        │   ← 進捗は常に見える
├──────────────────────────────────┤
│                                          │
│  アッバース朝が成立した年として            │
│  正しいものを選べ。                       │
│                                          │
│   ○ 661年                                │
│   ○ 732年                                │
│   ○ 750年                                │
│   ○ 762年                                │
│                                          │
└──────────────────────────────────┘
```

- **1画面1問。** スクロールさせない
- 選択肢のタップ位置は親指の届く下半分に置く
- 解答後は**即座に正誤と解説**を出す（`item.explanation` / `choices[].why_wrong`。事前生成済み）
- フラッシュカードは4ボタン固定（わからない／あいまい／わかった／余裕）。
  **表示から800ms未満の「わかった／余裕」は `q` を丸める**（`04b-spaced-repetition.md` §4.2）が、
  UI上は警告しない（責める体験にしない）

## 4. 教材ビューア

3,500字をスマホで読ませる。**離脱・進捗・中断が設計課題である**。

```
┌──────────────────────────────────┐
│ ← 戻る    イスラーム世界の形成    ⋮   │
│ ▓▓▓▓▓▓▓░░░░░░░░░░  §3 / 7  残り4分   │  ← 常時表示
├──────────────────────────────────┤
│  あなた向けのポイント                   │  ← 本文自体が個人向けに生成される
│ あなたは「ウマイヤ朝／アッバース朝」の      │
│ 区別で3回間違えています。§3-2 と §5 を    │
│ 特に注意して読んでください。              │
├──────────────────────────────────┤
│ §1 この単元で答えられるようになること      │
│  ...                                     │
│                                          │
│ §3 本文                                  │
│  ...                                     │
│                                          │
│ [ このセクションを読み終えた ]  ← 明示的  │
│                                          │
│ ▶ このセクションの理解を助ける動画        │
│  ┌──────────────┐                │
│  │  [サムネイル]      │  ← 2クリック   │
│  │  ▶ 再生            │                │
│  └──────────────┘                │
└──────────────────────────────────┘
```

| 課題 | 対策 |
|---|---|
| **離脱** | 上部に「§3/7・残り4分」を常時表示。7セクション構成なので終わりが見える |
| **進捗の可視化** | セクション単位のプログレスバー |
| **読了判定** | スクロール率だけで判定しない（飛ばしても100%になる）。**セクションごとの明示的な「読み終えた」ボタン** ＋ 滞在時間（`material_read.dwell_ms`）の両方を記録し、推定読了時間の60%以上滞在した場合のみ学習イベントとして扱う |
| **中断と再開** | 最後に読んだ `section_id` とスクロール位置を保存し、次回は「§3 の途中から再開しますか？」を出す |
| **長すぎる本文** | §3（1,600〜2,200字）は2〜4個の小見出しで分割される（`07-content-pipeline.md` §2） |

**動画は §7 の自己テストの前ではなく、各セクション末に置く**（`09b-video.md` §7）。
動画を閉じたら四択2問が出る。

### 4.1 教材の中の「調べる」（リサーチ）

本文に出てきた語を、**教材から離れずに**その場で引く。引く先は KC（`kc`）と正典
（`canon_event`）で、当たったものを **年表**（どの時代か）と **地図**（どの地域か）に置く。

```
┌──────────────────────────────────┐
│ この節について調べる            [開く] │
│ [ アッバース朝            ] [調べる]   │
│ 意味の近い項目を引くため、入れた語だけを   │
│ Google（Gemini API）へ送ります。        │
│ 「ウマイヤ朝」を調べる  ウマイヤ朝と…の違い  │  ← 本文の選択語 / この節の KC
├──────────────────────────────────┤
│ 「アッバース朝」: 8 件（語の一致 3・意味が近い 5）│
│  [世界地図: 関係する地域を塗る]           │
│  年表  □ 結果に合わせて拡大               │
│  時代 | 古代 | 中世 | 近世 |近代|現代|       │
│  西アジア  ▬ウマイヤ朝の成立 ▬アッバース朝… │  ← 行=地域、横=年
│  中国      ▬…                          │
│  750  出来事 アッバース朝の成立            │
│       8世紀・中世 ・ メソポタミア・イラン    │
└──────────────────────────────────┘
```

| 決定 | 理由 |
|---|---|
| **語の一致（ILIKE）と近傍検索（pgvector）を両方使い、語の一致を先に並べる** | 語だけだと「ウマイヤ朝」で「アッバース朝」（対になる語）が出ない。近傍だけだと綴りが一致する行が後ろに落ちることがある。どちらで当たったかは結果に持たせ、画面が隠さない |
| **ベクトルが無くても止めない** | 鍵が無い（フェイクの埋め込みは意味を持たない）／`PGVECTOR=off`／支出上限／索引が空、のどれでも語の一致で引き、**そう表示する** |
| **年表は行＝地域・横＝年。既定は前3000〜2000年の全範囲** | 「全史の中のどこか」がまず見えるべきである。近代に固まるときは「結果に合わせて拡大」で寄せる。年代の無い項目は置かず「年代なし」と一覧に出す（0年に置くのは嘘になる） |
| **地図は選んだ項目の地域、何も選んでいなければ結果の主地域** | 地域の付いた結果が無ければ地図そのものを出さない（塗る先の無い地図は場所を取るだけ） |
| **検索語だけを埋め込み API へ送り、送る前にそう書く** | `08` §4.1 の「自由入力を送らない」の例外（範囲指定の自然文と同じ扱い）。上限 60 字、UUID の混入は拒む |
| **開くまで何も引かない。KC のチップと本文の選択語からも引ける** | 検索は読書の脇道である。開かない人に費用も転送量もかけない。チップは飾りにしない |

埋め込み索引は `npm run db:embed-index -- --apply`（`scripts/db/embed-index.ts`）で作る。
空の行だけを埋め、鍵が無ければ拒む。時代区分（古代／中世／近世／近代／現代）は
`lib/domain/periods.ts` の表示用の概数であり、測定用の `era`（3区分）とは別である。

## 5. 確認テストの結果画面

`06-assessment.md` §6.2 の構成をそのまま使う。要点のみ再掲する。

- 素点を表示し、判定は `mastery` ベースで出す（合格／もう少し／要復習）
- 間違えた問題ごとに「**あなたが選んだB**」を明示し、そのBがなぜ誤りかを出す
- 「次にやること」を必ず出す。結果を見せて終わりにしない
- 再テスト可能日を明示する（3日後）

## 6. 集中特訓の作成フロー

```
[ + 新しい集中特訓 ]
      │
      ├─ ① 範囲を選ぶ
      │     ▸ 章立てから選ぶ（既定・チェックボックス）
      │     ▸ 文章で伝える（「ルネサンスから宗教改革あたり」）
      │        → AI が unit を提案 → ★確認画面で外せる（07 §8.2）
      │
      ├─ ② 締切を選ぶ（カレンダー）
      │
      ├─ ③ モードを選ぶ
      │     ▸ アプリの教材で学ぶ
      │     ▸ 自分で教科書を読む（問題と進捗管理だけ使う）
      │
      └─ ④ 確認
            「48KC / 12ユニット / あと24日 / 1日あたり約31問」
            ⚠️ 既存の『近代ヨーロッパ』と 62%（30KC）重複しています
               ▸ このまま作る  ▸ 重複部分を除いて作る
            [ 作成する ]
```

**作成前に1日あたりの量を見せる。** 作ってから「1日340問」と分かるのでは遅い。

## 7. 学習継続の仕組み

v0.1 には**通知・ストリーク・ゲーミフィケーションが完全に欠落**していた。
学習アプリの生死を分ける要素なので、最小構成を MVP に入れる。

| 仕組み | 実装 | 理由 |
|---|---|---|
| **連続学習日数** | ホーム右上に `12日連続`。`user_activity` から算出 | 最も費用対効果が高い。実装は数時間 |
| **1日1通のリマインド** | Vercel Cron（Hobby で1日1回）＋ Web Push または メール。ユーザーが時刻を選ぶ | 通知は1日1通に固定する。複数回送ると通知を切られ、二度と届かなくなる |
| **今日の達成** | 「今日やること 42問」の完了で祝う（控えめに） | |

**やらないこと**: ポイント・レベル・バッジ・ランキング。
非公開・数人での利用であり、競争の母集団が成立しない。ポイント設計は学習行動を歪めるリスクもある
（点を稼げる易しい問題ばかり解く）。

### 7.1 ストリークを壊さない配慮

「1日休むとゼロに戻る」は罪悪感で離脱を招く。

```
連続日数のカウントは「その日に1問以上解いた」で成立する（1問でよい）。
1日空いた場合は「ストリーク保護」を月2回まで自動適用する。
3日以上空いた場合はリセットするが、「これまでの最長記録: 24日」を残す。
```

## 8. デザイン方針（見た目）

**Litverse Design System v1.0 を採用する。詳細は [`11b-design-system.md`](./11b-design-system.md)。**

v0.1 の「シンプルかつクール」は、装飾を足すのではなく
**「紙・墨・朱・蛍光の4色だけ」「等幅書体」「影とグラデーション禁止」「余白は4の倍数のみ」**
という制約によって達成する。

| 項目 | 決定 |
|---|---|
| デザインシステム | **Litverse v1.0**（`docs/design/litverse.css` ＋ `historia-overrides.css`） |
| 配色 | 紙 `#FCF6E8` / 墨 `#171512` / 朱 `#F4703C` / 蛍光 `#FCE04A`。**使用比率 70:20:7:3** |
| 書体 | 和文 M PLUS 1 Code / 欧文 Space Mono（**いずれも等幅**） |
| 本文 | 14px / 行間 1.9。教材ビューアのみ 14/16/18 を切替可（§4） |
| 罫線 | 1px（区切り）/ 1.5px（カード外周）/ 1px 破線（補助） |
| 角丸 | 0 / 4 / 6 のみ |
| 余白 | 4 の倍数のみ |
| アイコン | **活字グリフ**（⌂ ⌕ ❑ ← ↗ ⋮ ☰ ◔ ▶）。アイコンライブラリと色付き絵文字は使わない |
| 影・グラデーション | **禁止**（`box-shadow` / `linear-gradient` を書かない） |
| ダークモード | 作らない（紙の意匠が前提） |
| コンポーネント | `lv-*`（Litverse）＋ `hs-*`（HISTORIA 固有）。shadcn/ui は使わない |

**「UIは機能完成後」という v0.1 の方針について。** 見た目（配色・書体・余白）を後回しにするのは
正しかったが、それは**デザインシステムが決まっていれば**という条件付きである。
Litverse を採用したことで見た目の判断はトークンに固定されたため、
実装者は「何色にするか」を毎回考えずに済む。**情報設計（§1〜§7）だけが設計対象として残る。**

主要8画面のモックは `docs/design/historia-screens.html` にあり、
Chromium で描画して崩れがないことを確認済み（`11b-design-system.md` §8）。

## 9. ナビゲーション

v0.1 は「タイムラインの導線をフッタにする」としていたが、**タイムラインは Phase2 に回った**。

MVP のフッタは3タブとする。

| タブ | 内容 |
|---|---|
| **ホーム** | 今日やること・進行中の特訓 |
| **特訓** | 特訓の一覧と詳細（教材・進捗・確認テスト） |
| **記録** | 学習履歴・弱点の一覧と根拠（`04-weakness-engine.md` §4.3）・ストリーク |

「記録」タブに**弱点の根拠**を出すことが重要である。
