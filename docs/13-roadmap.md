# 13. 開発ロードマップ

> 対象: HISTORIA / 状態: 確定 / 最終更新: 2026-09-01

## 0. 前提

- 開発者は**1名**（大学生インターン、Claude Code を使用）
- 可処分時間は **週15時間**（平日2時間＋週末）
- 総工数の見積りは **77人日**（`01-product.md` §5）＝ 約616時間 → **週15時間で約41週**

**41週（10ヶ月）は長すぎる。** そのままでは受験のサイクルに間に合わない。
したがって次の2つの手を打つ。

1. **Phase 0 で仮説を先に検証する。** 77人日を投じる前に、2週間と無料枠の RPD 40件で前提を確かめる
2. **KC シードを 800〜900件全部作らない。最初は共通テスト頻出の 400件に絞る**（作者判断）
   工数12人日 → 6人日。KC は追加しても既存データを壊さないので、範囲が足りなくなったら足す

**v0.3 でカタログ構築（10人日）が消えた**代わりに、非同期ジョブ基盤（5人日）と
正典マスタの倍増（+2人日）・診断プール（+2人日）が加わった。差し引きはほぼ同じである。

これで MVP までを **約24週（6ヶ月）** に短縮する。

## Phase 0 — 仮説検証（2週間 / 課金は約500円）

**目的: 「AI が生成した教材と問題で受験世界史の学習が成立するか」を、実装前に確かめる。**

| # | やること | 成果物 |
|---|---|---|
| 0-1 | 共通テスト過去問（世界史探究）1年分を作者が解き、正答率と落とした範囲を記録する | 事前測定の記録 |
| 0-2 | ~~20ユニット分の KC と `canon_event`~~ **完了（2026-09-02）**。KC は 408件（75/75節）、正典は `canon_event` 1,180件・`person` 446件。範囲を落とさず全範囲を作った | `seed/kc.csv` / `seed/canon_event.csv` / `seed/person.csv` |
| 0-3 | `07-content-pipeline.md` §5 のプロンプトで20ユニットの教材＋item を **Gemini 無料枠で**生成する | 教材20本・item 約400問 |
| 0-4 | **生成物の年号・人名の誤りを人手で全数チェックする** | 誤り混入率の実測値 |
| 0-4e | **層5を通した結果、20本中何本が配信できたかを数える** | **Phase 0 の主判定指標**（85%以上） |
| 0-4a | **層3（別系統の課金モデルによる二次照合）を回し、0-4 で見つけた誤りをどれだけ検出できるか測る** | 層3の検出率。**人手レビューの代替が機能するかの判定** |
| 0-4d | **judge を回し、distractor と因果の説明の質を測る**（機械照合では守れない領域） | judge の軸別スコア |
| 0-4b | **`claims` を `canon_event` に当てて機械照合率を測る** | 照合率（目標80%以上） |
| 0-4c | Gemini の構造化出力（`responseSchema`）がスキーマどおり通るか確認する | 通過率 |
| 0-5 | `08-ai-architecture.md` §9 の10単元で拒否・婉曲が起きないか確認する | 拒否事例の一覧 |
| 0-6 | 無料枠の実際の RPM / RPD / TPD と、1ユニットの生成所要秒数を実測する | レート設計とタイムアウトの補正 |
| 0-7 | 生成された問題を紙／スプレッドシートで2週間解く（アプリは作らない） | 学習記録 |
| 0-8 | 別年度の過去問を解き、事前事後を比較する | 事後測定の記録 |

### 判定基準（これを満たさなければ設計を見直す）

| 指標 | 基準 | 満たさない場合 |
|---|---|---|
| **配信できたユニット数** | 20ユニット中 **17本（85%）以上** | 誤りが検出された教材は配信しない設計にしたため（`08` §5 層5）、事実誤りは「教材が出ない頻度」として現れる。85%を下回るならプロンプトを直す。直らなければ (a) 正典マスタを厚くする (b) 生成も課金モデルに上げる (c) 共有カタログ方式に戻す。**(c) が最も安い**（`08` §3.5） |
| 教材の事実誤り（参考値） | 20ユニットで3件以下 | 配信を止める設計があるので**受験生には届かない**。ただし生成品質の指標として測る |
| **層3の検出率** | 0-4 の誤りの **70%以上**を検出できる | 検出できないなら人手レビューの代替が成立していない。検証モデルを上げるか共有カタログに戻す |
| **judge の distractor 軸** | 4点以上（5点満点） | Flash が落ちるとしたらここ。生成モデルを上げるか、設問だけ課金モデルにする |
| **機械照合率** | `year` / `person` の claim の **80%以上** | `canon_event` を追加する。ここが通らないと誤情報を検出できない |
| 1ユニットの生成時間 | **240秒以内** | 超えるなら教材を短くする（Vercel の300秒上限） |
| 生成問題の質 | 「消去法で瞬時に切れる誤答」が2割以下 | distractor のプロンプトを作り直す |
| 学習効果 | 事後の該当範囲の正答率が事前より **+15pt 以上** | KC の粒度か問題の形式を見直す |
| モデルの拒否 | 10単元で拒否・過度な婉曲が **0件** | システムプロンプトを調整。それでも駄目なら該当単元は人手執筆 |

**Phase 0 を飛ばして実装に入らない。** ここで偽と分かれば、78人日を節約できる。

| 5 | **非同期ジョブ基盤**（キュー・ポーリング・先読み・リトライ）＋生成パイプライン（Gemini無料枠）＋`canon_event` 照合＋**層3の二次照合（Anthropic課金）**＋層5（FLAG段落の非表示） |

**Phase 1 完了の条件**: 作者が「診断 → 今日やること → 解く → 弱点が更新される → 翌日出し直される」を
**7日連続で体験できる**こと。

この時点でまだ無いもの: 集中特訓（締切逆算）、確認テスト、動画、通知。
それでも**閉ループは回る**。ここが最も重要なマイルストーンである。

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **KC シードの作成が想定より重い** | 全体が2〜4週遅延 | Phase 1 の週3-4で実測し、遅ければ初期シードを400→250件に減らす |
| Phase 0 で学習効果が確認できない | 設計の作り直し | **だから Phase 0 を最初に置いている**。2週間・約500円で分かる |
| **教材の事実誤りが多い** | **人手レビューが無いため直接ユーザーに届く** | 正典マスタを厚くする。層5（検証できない段落を出さない）で被害を止める。それでも駄目なら有料モデルか共有カタログに戻す |
| **無料枠の条件が変わる** | 生成が止まる、または課金される | プロバイダ抽象層で切り替える（`08` §6）。退避先の金額は `12-nonfunctional.md` §2.2 |
| 作者の可処分時間が減る（学業・インターン） | 全体が遅延 | Phase の境界で必ず「動くもの」が残る構成にしてある。どこで止まっても価値がある |


## 各 Phase で「動くもの」が残ること

このロードマップの設計原則は、**どの Phase の終わりで止まっても使えるものが残る**ことである。

| 止まった時点 | 残るもの |
|---|---|
| Phase 0 | 20ユニットの教材と400問（紙で使える）＋誤り混入率・照合率・層3検出率・judge スコアの実測値 |
| Phase 1 | 診断＋出題＋弱点追跡＋教材（毎日使える） |
| Phase 2 | ＋ 締切逆算と確認テスト（受験計画に使える） |
| Phase 3 | ＋ 動画と継続の仕組み（人に見せられる） |
