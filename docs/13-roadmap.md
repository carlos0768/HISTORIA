# 13. 開発ロードマップ

> 対象: HISTORIA / 状態: 確定 / 最終更新: 2026-09-01

## 0. 前提

- 開発者は**1名**（大学生インターン、Claude Code を使用）
- 可処分時間は **週15時間**（平日2時間＋週末）
- 総工数の見積りは **78人日**（`01-product.md` §5）＝ 約620時間 → **週15時間で約41週**

**41週（10ヶ月）は長すぎる。** そのままでは受験のサイクルに間に合わない。
したがって次の2つの手を打つ。

1. **Phase 0 で仮説を先に検証する。** 78人日を投じる前に、400円と2週間で製品の前提を確かめる
2. **カタログを400ユニット全部作らない。** 最初は共通テスト頻出の120ユニットに絞る
   （工数10人日 → 3人日、コスト5,900円 → 1,800円）

これで MVP までを **約24週（6ヶ月）** に短縮する。

## Phase 0 — 仮説検証（2週間 / 約400円）

**目的: 「AI が生成した教材と問題で受験世界史の学習が成立するか」を、実装前に確かめる。**

| # | やること | 成果物 |
|---|---|---|
| 0-1 | 共通テスト過去問（世界史探究）1年分を作者が解き、正答率と落とした範囲を記録する | 事前測定の記録 |
| 0-2 | 落とした範囲に対応する **20ユニット** の KC を手で作る（約220件） | KC の CSV |
| 0-3 | `07-content-pipeline.md` §5 のプロンプトで20ユニットの教材＋item を生成する | 教材20本・item 約400問 |
| 0-4 | **生成物の年号・人名の誤りを人手で全数チェックする** | 誤り混入率の実測値 |
| 0-5 | `08-ai-architecture.md` §7.1 の10単元で拒否・婉曲が起きないか確認する | 拒否事例の一覧 |
| 0-6 | `count_tokens` で日本語1文字あたりのトークン数を実測する | 原価試算の補正 |
| 0-7 | 生成された問題を紙／スプレッドシートで2週間解く（アプリは作らない） | 学習記録 |
| 0-8 | 別年度の過去問を解き、事前事後を比較する | 事後測定の記録 |

### 判定基準（これを満たさなければ設計を見直す）

| 指標 | 基準 | 満たさない場合 |
|---|---|---|
| 教材の事実誤り | 20ユニットで**3件以下** | プロンプトを直す。直らなければ人手執筆の比率を上げる |
| 生成問題の質 | 「消去法で瞬時に切れる誤答」が2割以下 | distractor のプロンプトを作り直す |
| 学習効果 | 事後の該当範囲の正答率が事前より **+15pt 以上** | KC の粒度か問題の形式を見直す |
| モデルの拒否 | 10単元で拒否・過度な婉曲が **0件** | システムプロンプトを調整。それでも駄目なら該当単元は人手執筆 |

**Phase 0 を飛ばして実装に入らない。** ここで偽と分かれば、78人日を節約できる。

## Phase 1 — 基盤と閉ループの最小実装（8週間）

**目的: 1人（作者）が実際に毎日使える最小のループを動かす。**

| 週 | やること |
|---|---|
| 1 | Next.js（App Router）＋ Supabase のセットアップ。`schema.sql` を適用。Supavisor 経由の接続を確認 |
| 2 | 認証（Google ログイン）＋招待コード＋生年月日＋同意フロー。RLS の動作確認 |
| 3-4 | **KC シードの作成（120ユニット分・約350件）**。AI 提案 → 作者承認のスクリプトと CSV 管理 |
| 5 | カタログ構築スクリプト（Batches API・冪等）＋ judge ＋ `canon_event` 照合。120ユニット分を生成 |
| 6 | 出題エンジン: `card` の取得、`response` の記録、BKT/Elo 更新、SM-2 更新 |
| 7 | 出題UI（四択・フラッシュカード）＋結果表示。教材ビューア（進捗保存・中断再開） |
| 8 | 診断テスト＋ホーム（今日やること）。**作者が毎日使い始める** |

**Phase 1 完了の条件**: 作者が「診断 → 今日やること → 解く → 弱点が更新される → 翌日出し直される」を
**7日連続で体験できる**こと。

この時点でまだ無いもの: 集中特訓（締切逆算）、確認テスト、動画、通知。
それでも**閉ループは回る**。ここが最も重要なマイルストーンである。

## Phase 2 — 集中特訓と確認テスト（5週間）

| 週 | やること |
|---|---|
| 9 | 集中特訓の作成フロー（章立て選択・締切・モード）＋重複警告 |
| 10 | スケジューラ（`daily_plan()`・複数特訓の総量調停・達成不能の警告） |
| 11 | 確認テスト（層化抽出・14日以内の再出題禁止・合否判定） |
| 12 | 確認テスト結果画面（誤答解説・次にやること）＋`misconception` 検出 |
| 13 | 「記録」タブ（弱点一覧＋根拠の表示）。**アルゴリズムのデバッグ手段になるので早めに作る** |

**Phase 2 完了の条件**: 「範囲と締切を決める → 毎日の量が自動で決まる →
確認テストで合否が出る → 落とした項目が翌日に戻ってくる」が動くこと。

## Phase 3 — 動画・継続・仕上げ（5週間）

| 週 | やること |
|---|---|
| 14 | YouTube: `channel_allowlist` の選定、`playlistItems.list` での候補収集、埋め込みでの KC 対応付け |
| 15 | 動画の埋め込みUI（2クリック）＋視聴後 retrieval ＋週次の生存確認バッチ |
| 16 | ストリーク＋1日1通のリマインド通知。空状態の作り込み |
| 17 | 誤り報告導線、管理者ビュー（コスト・未処理報告）、監視（Sentry・`ops_log`） |
| 18 | 残りのカタログ生成（120 → 280ユニット）＋人手レビュー |

## Phase 4 — 実利用と修正（4週間）

| 週 | やること |
|---|---|
| 19 | 友人3人を招待。オンボーディングの詰まりを観察する |
| 20-21 | 実データに基づくパラメータ調整（`04-weakness-engine.md` §9 の提案値を実測で補正） |
| 22 | `04b-spaced-repetition.md` §4.3 の `median_latency` を実測値に切り替え |

**この段階で初めて閾値をいじる。** `response` が不変ログなので、
閾値を変えても `algo_version` を上げて再計算するだけで済む（履歴を失わない）。

## Phase 5 以降（MVP 完了後）

優先順位順。**すべて MVP の閉ループが回ってから着手する。**

| # | 機能 | 前提 |
|---|---|---|
| 1 | **Wiki 用語マスタと用語リンク** | `term` / `term_alias` の構築（`09-content-sourcing.md` §4.2） |
| 2 | **模試の成績表・解答用紙の取り込み** | Vision LLM の精度検証（`04-weakness-engine.md` §6） |
| 3 | **歴史タイムライン** | 事前バッチ生成 6,000記事（約2,700円）（`09` §3） |
| 4 | **過去問DB** | 権利処理の確認から。3〜5大学 × 3年分で開始（`10-legal-risk.md` §3） |
| 5 | ユーザー任意範囲の即時教材生成 | ジョブ基盤の導入（`08-ai-architecture.md` §6.3） |
| 6 | 一般公開 | **`10-legal-risk.md` §4.3 の公開前チェックリストをすべて満たすこと** |

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| **KC シードの作成が想定より重い** | 全体が2〜4週遅延 | Phase 1 の週3-4で実測し、遅ければカタログを120→80ユニットに減らす |
| Phase 0 で学習効果が確認できない | 設計の作り直し | **だから Phase 0 を最初に置いている**。2週間・400円で分かる |
| 教材の事実誤りが多い | ファクトチェック工数が膨らむ | `canon_event` を厚くする。それでも駄目なら人手執筆の比率を上げる |
| 作者の可処分時間が減る（学業・インターン） | 全体が遅延 | Phase の境界で必ず「動くもの」が残る構成にしてある。どこで止まっても価値がある |
| モデルの料金改定 | 原価が変動 | カタログは一度きりの費用なので影響は限定的。ランニングは月160円で余裕がある |

## 各 Phase で「動くもの」が残ること

このロードマップの設計原則は、**どの Phase の終わりで止まっても使えるものが残る**ことである。

| 止まった時点 | 残るもの |
|---|---|
| Phase 0 | 20ユニットの教材と400問（紙で使える） |
| Phase 1 | 診断＋出題＋弱点追跡＋教材（毎日使える） |
| Phase 2 | ＋ 締切逆算と確認テスト（受験計画に使える） |
| Phase 3 | ＋ 動画と継続の仕組み（人に見せられる） |
