# 06. 確認テスト・出題設計

> 対象: HISTORIA MVP / 状態: 確定 / 最終更新: 2026-09-01

## 0. この文書が解く問題

v0.1 は「**しかしどちらにしても最終的には確認テストをアプリ側で行う**」としか書いておらず、
問題数・形式・出題選択・合格基準・フィードバックのすべてが空白だった。

## 1. 出題形式（対象試験に合わせて確定）

対象は**共通テスト中心＋私大マーク**であり、国公立二次の論述は対象外である（`01-product.md`）。
したがって全形式で**自動採点が成立する**。LLM 採点は使わない（コストゼロ・レイテンシゼロ・非決定性ゼロ）。

| 形式 | `item.format` | `guess_rate` | 用途 |
|---|---|---|---|
| 四択 | `mcq4` | 0.25 | 主力。共通テストの資料読解型も四択で模す |
| 一問一答（記述） | `cloze` | 0.05 | 用語の想起。表記ゆれは `person.aliases` で吸収 |
| 正誤判定 | `tf` | 0.50 | 私大マークの正誤問題型 |
| 年代並べ替え | `order` | `1/n!` | `kind=chronology` のKC専用 |
| フラッシュカード | `flashcard` | 0.02 | 自己申告。測定ではなく学習用（§5） |

**論述・記述式の AI 採点は実装しない。** これは対象試験の決定から導かれる帰結であり、
「今は作らない」ではなく「**この製品の仕様に含めない**」と明記する。

## 2. 出題選択アルゴリズム

### 2.1 ランダム出題を採用しない理由

ランダムは実装が最も簡単だが、測定器として最悪である。

| 問題 | 帰結 |
|---|---|
| カバレッジが保証されない | 範囲48KCから20問をランダムに引くと、運悪く同じ8KCに偏り「範囲を仕上げたか」を判定できない |
| 既に `mastered` のKCに枠を浪費する | 20問中12問が既知の項目になり、測定効率が半減する |
| 難易度が制御できない | 全問正解か全問不正解になると、`theta` の更新量がほぼゼロになる（情報量が最小） |
| 逐語再認を防げない | 直前に読んだ教材の例文がそのまま出て、記憶ではなく残像で正解する |

### 2.2 決定: 層化抽出 ＋ 難易度適応 ＋ 再出題禁止期間

```python
def build_check_test(user, drill, today):
    kcs = drill_kc[drill.id]

    # 自学モードは教材が無いので範囲全体から出す（§4）
    if drill.mode == 'ai_material':
        kcs = [k for k in kcs if k in covered_by_materials(drill)]

    N = clip(ceil(len(kcs) * 0.35), 10, 25)

    ranked = sorted(kcs, key=lambda k: mastery(user, k))
    weak_pool   = ranked[: ceil(len(ranked) * 0.6)]     # 弱い方から60%
    strong_pool = ranked[ceil(len(ranked) * 0.6) :]     # 残り40%

    picked_kcs = sample_without_replacement(weak_pool,   round(N * 0.7)) \
               + sample_without_replacement(strong_pool, N - round(N * 0.7))

    items = []
    for kc in picked_kcs:                               # 同一KCから2問以上出さない
        cands = [i for i in items_of(kc)
                 if i.approved
                 and not answered_within(user, i, days=14)]   # 逐語再認の回避
        if not cands:
            cands = [i for i in items_of(kc) if i.approved]   # 全部最近解いていたら妥協
        if not cands:
            continue
        # 期待正答率が 0.6 に最も近い item を選ぶ（情報量が最大の帯）
        items.append(min(cands, key=lambda i: abs(p_expected(user, kc, i) - 0.6)))

    return shuffle(items)
```

**弱点層だけから出さない**（0.7 : 0.3 の配分）。習得済みの層も測らないと
「範囲を仕上げた」と言えないし、忘却の検出もできない。

**`answered_within(user, item, days=14)` が本アプリ固有の重要なガードである。**
v0.1 は「教材を読む → 確認テスト」を連続した体験として設計していたが、
教材直後に同じ内容を問うと**教材の逐語再認で正解でき、入試本番の初見問題への転移が起きない**。
確認テストは「教材を読んだかの測定器」ではなく「知識が定着したかの測定器」でなければならない。

### 2.3 教材と確認テストの間に時間差を置く

```
教材の読了 → 確認テストの受験可能化までに最低 1 日空ける。
読了直後に出すのは「理解確認クイズ」（2〜3問・記録は残すが drill の合否には使わない）とし、
「確認テスト」とは UI 上も明確に分ける。
```

これは分散学習（distributed practice）の原則に基づく。
Dunlosky et al. (2013) の10手法レビューでは、practice testing と distributed practice が
high utility、rereading は low utility と評価されている。

## 3. 合否判定

### 3.1 素点で判定しない

四択は25%で当たるため、素点80%は真の習得率73%程度に相当する。
形式が混在するテストでは素点の意味がさらに曖昧になる。

**決定: 表示は素点、判定は `mastery` で行う。**

```
表示:  18 / 22 問正解（81.8%）

判定:  テスト結果を user_kc_state に反映した後の drill 進捗率で決める
       合格     … 進捗率 >= 0.85
       もう少し … 0.60 <= 進捗率 < 0.85
       要復習   … 進捗率 <  0.60
```

進捗率の定義は `05-scheduler.md` §6（`mastered` なKCの割合）と同一である。
**同じ数字を2つの定義で計算しない。**

**確認テストの「合格」（0.85）と、集中特訓の「完了」（0.90、`05-scheduler.md` §6.1）は別物である。**
合格は「この時点で仕上がってきている」という中間評価であり、完了は特訓そのものの終了条件である。
0.85〜0.90 の帯では「合格。あと少しで特訓が完了します」と表示する。

### 3.2 不合格時の扱い — 「戻る」も「進む」もしない

v0.1 は不合格時の挙動を定義していなかった。

**決定: 特訓は継続し、落としたKCが自動的に翌日以降のキュー先頭に来る。**

これは新しい仕組みを必要としない。SM-2 は誤答で `interval = 1` にリセットするため
（`04b-spaced-repetition.md` §3）、落とした item は翌日に due になる。
`05-scheduler.md` §4.2 の priority は `mastery` が低いものを上位に置くため、自然に先頭へ来る。

**再テストは前回受験から3日以上空ける。** 連続受験を許すと、
テストが「覚えているか」ではなく「さっきの問題を覚えているか」の測定になる。

### 3.3 教材にない知識を問わない保証

```
item ─ item_kc ─ kc ─ material_section_kc ─ material_section ─ material
```

`mode = 'ai_material'` の drill では、確認テストの出題対象を
**「その drill で生成済みの教材がカバーしているKC」に限定する**（§2.2 の `covered_by_materials`）。

`mode = 'self_study'`（ユーザーが自分で学習する）の場合は教材が存在しないため、
`drill_kc` 全体から出す。この場合はテスト開始前に明示する。

> このテストは、あなたが指定した範囲全体から出題します。
> アプリ内に教材はないため、教科書・参考書で学習した内容から出ます。

## 4. シグナルの信頼度

フラッシュカード・四択・確認テストは**同じ「correct=true」でも情報量が違う**。
`guess_rate` は「まぐれ当たり率」を扱うが、「**自己申告の甘さ**」は別の問題である。

**決定: `response.weight` で二重に割り引く。**

| `session_kind` / `format` | `weight` | 理由 |
|---|---|---|
| `checktest`（客観形式） | 1.0 | 最も信頼できる |
| `quiz`（四択） | 1.0 | 客観 |
| `diagnostic` | 1.0 | 客観 |
| `video_retrieval` | 1.0 | 客観 |
| `flashcard` | **0.7** | 自己申告。正誤の基準が本人依存 |
| `import`（画像取り込み） | **0.5** | 本人申告かつ Vision の誤認識リスク |

`weight` は `04-weakness-engine.md` の `theta` 更新と `n_eff` の両方に乗る。

### 4.1 フラッシュカードだけでは `mastered` にしない

`04-weakness-engine.md` §2 の `mastered` 条件に、次の1条件を追加する。

```
'mastered' if mastery >= 0.85
              and n_eff >= 3
              and count(distinct date(answered_at)) >= 2
              and exists(response WHERE format != 'flashcard' AND correct)   -- ★追加
```

自己申告だけで習得済みにできると、「わかった」を連打するだけで進捗率が100%になる。

## 5. 自己欺瞞への耐性

| 抜け道 | 対策 | 実装場所 |
|---|---|---|
| 答えを見てから「わかった」を押す | 表示から 800ms 未満の「わかった／余裕」は `q = min(q, 3)` に丸める | `04b` §4.2 |
| フラッシュカードだけを回す | `mastered` に客観形式での正解を必須にする | §4.1 |
| 四択を連打して当てる | `n_eff += w·(1-g)` で証拠を割り引く | `04-weakness-engine.md` §1.2 |
| 確認テストを連続受験して丸暗記する | 再テストは3日以上空ける | §3.2 |
| 教材を読んだ直後にテストを受ける | 教材読了から1日空ける／14日以内の再出題を禁止 | §2.2, §2.3 |

**カンニングは検出しない。** 学習アプリの利用者は自分のために使っているので、
本気の不正対策は費用対効果が合わない。上記は「**うっかり自分を騙してしまう**」ことへの耐性であり、
悪意への対策ではない。

## 6. 誤答フィードバック

### 6.1 事前生成する

都度生成の場合、1回の誤答ごとに LLM 呼び出しが発生する。
確認テスト1回で4問落とすと4回、レイテンシは各2〜4秒。**コストとレイテンシの両方で不利**である。

**決定: `item` の生成時に、本文・選択肢・正答と同時に解説を構造化出力させる**
（`07-content-pipeline.md` の JSON Schema に `explanation` と `distractor_explanations` を含める）。

```sql
-- item テーブル（抜粋。全体は 03-data-model.md）
explanation             text NOT NULL,     -- 正答の解説（150〜250字）
distractor_explanations jsonb,             -- {"b": "アッバース朝は750年成立で…", ...}
```

**誤答選択肢ごとの解説を持つ**ことが重要である。「正解はCです」ではなく
「あなたが選んだBのアッバース朝は750年成立で、この時期はまだウマイヤ朝です」と返す。
これが `misconception` の解消に直結する。

### 6.2 結果画面の構成

```
確認テスト 結果
─────────────────────
18 / 22 問正解      判定: もう少し（進捗 72%）

▼ 間違えた問題（4問）
  [1] 設問文
      あなたの解答: B（アッバース朝）      正解: C（ウマイヤ朝）
      → アッバース朝は750年成立で、この時期はまだウマイヤ朝です。
      📺 このあたりを解説している動画（1件）      ← 09b-video.md §7
      📖 教材「イスラーム世界の形成」§3 を読み直す

▼ 次にやること
  この4項目は明日の学習キューの先頭に入りました。
  再テストは 3日後（9/4）から受けられます。
```

## 7. 診断テストとの違い

| | 診断テスト | 確認テスト |
|---|---|---|
| 目的 | 出題順の初期化 | 範囲を仕上げたかの判定 |
| 対象 | 全範囲（`exam_weight` 上位） | 1つの drill の範囲 |
| 問数 | 12〜24（適応打ち切り） | 10〜25（範囲サイズの35%） |
| 抽出 | facet 被覆優先 | KC 層化（弱点70% / 習得30%） |
| 結果の扱い | `theta` のみ更新、`n_eff = 0` のまま | 通常の応答として全面的に反映 |
| 合否 | なし | あり（§3） |
| 頻度 | 初回1回のみ | drill ごと・3日間隔 |

診断テストの詳細は `04-weakness-engine.md` §5 を参照。
