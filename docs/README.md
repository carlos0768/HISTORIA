# HISTORIA 要件定義書 v0.2

受験世界史（歴史総合・世界史探究）向け学習アプリ HISTORIA の設計書。
v0.1（構想メモ 30行）を、着工可能な粒度まで具体化したもの。

> **v0.2 は仕様であり、実装コードはまだ存在しない。**
> `schema.sql` のみ PostgreSQL 16 で実行検証済み（`03-data-model.md` §8）。

## 一言でいうと

**HISTORIA は、受験世界史の「何を忘れているか」を測り続け、忘れる直前に出し直す学習アプリである。**

差別化は教材の質ではなく、**学習履歴の蓄積と、それに基づく出題タイミングの制御**にある
（「ChatGPT に直接聞けばよいのでは？」への回答は `01-product.md` §2）。

## v0.1 から変わった主なこと

v0.1 の監査（12レンズ）で **blocker 7件・high 18件** が出た。主要な変更は次のとおり。
全一覧は [`14-open-questions.md` §6](./14-open-questions.md)。

1. **弱点を「人物・時代・地域」の3軸で持つのをやめ、KC モデルにした**
   3軸は事象を指す座標であって「できないことの型」ではない。「宗教改革の因果が分からない」
   「条約名と年号が結びつかない」はどの軸にも入らなかった → `02-domain-model.md` §1
2. **`AIプロバイダー=GCP` × `使用モデル=ChatGPT` の矛盾を解消した**
   Vertex AI に OpenAI の商用 API は無い → Anthropic 直 API に1本化 → `08-ai-architecture.md` §1
3. **教材を「共有カタログ＋個人差分」にした**
   原価がユーザー数に対して O(1) か O(N) かの分岐点。ファクトチェックの可否がこれを決めた
   → `07-content-pipeline.md` §3
4. **範囲の分割を AI に任せるのをやめた**
   分割が非決定的だと「一日にこなすべき量」の逆算が成立しない → `02-domain-model.md` §4.4
5. **弱点をイベントソーシングにした**
   `response` を不変の追記専用ログとし、弱点は導出テーブルにした。
   閾値を変えても学習履歴を捨てずに再計算できる → `04-weakness-engine.md` §4
6. **確認テストの設計を全面的に定義した**
   教材直後に同じ内容を問うと逐語再認で正解でき、入試本番への転移が起きない
   → `06-assessment.md` §2.2
7. **過去問DB・タイムライン・Wiki を Phase2 に移した**
   閉ループに寄与しない。ただし後から変更できないスキーマだけは MVP で確定した

## 執筆規則

- 曖昧語（色々／かなり／死ぬほど／whatever／適切に）を使わない。**すべて数値と定義に置き換える**
- 「〜を検討する」ではなく「〜とする」と断定する
- 数値には根拠を付ける。根拠のないものは **要検証** と明記する
- 提案値であるパラメータは各章末の一覧表に集約し、`algo_version` で管理する
