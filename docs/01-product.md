# 01. プロダクト定義とスコープ

> 対象: HISTORIA / 状態: 確定（v0.3） / 最終更新: 2026-09-01

## 1. 一言でいうと

**HISTORIA は、受験世界史の「何を忘れているか」を測り続け、忘れる直前に出し直す学習アプリである。**

対象は共通テスト（歴史総合、世界史探究）＋私立大学のマーク式入試を受ける高校生。
非公開・招待制で、作者と友人数人が使う。

## 2. 「ChatGPT に直接聞けばよいのでは？」への回答

この問いに答えられなければ、この製品に存在意義はない。正面から答える。

### 2.1 ChatGPT にできて HISTORIA にできないこと

- 任意の質問に即座に答える
- 教材を書く（**これは HISTORIA も同じ系統のモデルを使うので、品質差はほぼない**）
- 対話しながら理解を深める

**教材生成の質そのものは差別化にならない。** 同じ系統のモデルを呼んでいるからである。
「AIが教材を作ってくれる」だけの製品なら、ChatGPT に「フランス革命を高校生向けに解説して」と
打つのと変わらない。v0.1 が「教材は死ぬほどこだわるべき」を中核価値に置いていたのは、
**差別化の軸を誤っている**。

**教材を毎回生成する（v0.3）ことは、この結論を変えない。**
ChatGPT に自分の弱点を毎回説明すれば同じものが得られる。
HISTORIA の価値は「**弱点を説明しなくてよい**」ことにある。
それは §2.2 のとおり、履歴を持っていることから来る。

### 2.2 ChatGPT にできないこと

| | ChatGPT | HISTORIA |
|---|---|---|
| あなたが**何を間違えたか**を覚えている | ✗ | ✅ `response`（不変ログ）＋ `user_kc_state` |
| **いつ忘れるか**を推定して出し直す | ✗ | ✅ SM-2 ＋ `0.9^(t/I)` の保持率推定 |
| 同じ誤答を**繰り返している**ことに気づく | ✗ | ✅ `misconception`（同じ選択肢を2回以上） |
| **締切から逆算**して1日の量を決める | ✗ | ✅ `daily_plan()` |
| 出題の**難易度を合わせる** | ✗ | ✅ θ 推定＋実測難易度（`04b` §5.1） |
| 推測正解を**割り引く** | ✗ | ✅ `n_eff += w(1-g)` |
| 事実誤りを**検証**してから出す | ✗ | ✅ ファクトチェック4層＋人手レビュー |

**ChatGPT は優秀な教材生成器だが、学習の管理者ではない。**
HISTORIA の価値は教材の質ではなく、**学習履歴の蓄積と、それに基づく出題タイミングの制御**にある。

### 2.3 既存の学習アプリとの違い

| 製品 | できること | HISTORIA との違い |
|---|---|---|
| **Anki** | 間隔反復は完璧 | **カードを自分で作らなければならない**。受験世界史のカードを800枚作る作業自体が最大の障壁。HISTORIA はカードが最初から入っており、教材と同じKC体系で紐づいている |
| **一問一答アプリ** | 用語の暗記 | 単語レベルしか扱わない。**「区別」「因果」「年代順」を弱点として持てない**（`02-domain-model.md` §1）。共通テストの因果理解型の出題に対応できない |
| **スタディサプリ等の動画講義** | 講義の質 | 弱点の粒度が「単元」止まりで、KC単位の測定がない。視聴の記録はあるが**習得の測定がない** |
| **赤本・過去問サイト** | 問題の量と権威 | 解いた結果が蓄積されず、次に何をやるべきかを教えてくれない |

**HISTORIA の一点: 受験世界史に特化した KC 体系の上で、教材・問題・忘却スケジュールが
1つの閉ループになっていること。**

## 3. 閉ループ

```
   診断テスト ──► user_kc_state（何が弱いか）
                        │
                        ▼
              daily_plan（今日やること）
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
      教材            四択/FC          動画
        │               │               │
        └──────► response（不変ログ）◄──┘
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
  user_kc_state      card(SM-2)    misconception
   (習得度)         (次はいつ)      (何と混同)
        └───────────────┴───────────────┘
                        │
                        ▼
                  確認テスト（合否）
                        │
                        └──► 落としたKCが翌日のキュー先頭へ
```

**このループのどこか1つでも欠けると、製品は「AI教材ビューア」に退化する。**
だから MVP はこのループを丸ごと作る（§4）。

### 4.2 Phase2 に回すもの（作者が明示的に決定）

| 機能 | 理由 | MVP でやっておくこと |
|---|---|---|
| **過去問DB** | 権利処理と PDF/OCR の工数が大きい。閉ループには不要 | 要素分解スキーマと `CONTENT_MODE` を先に確定（`10-legal-risk.md` §3.3, §4） |
| **歴史タイムライン** | 学習の閉ループに寄与しない。フッタ導線も Phase2 | 多列（地域レーン）方式と事前生成方針を確定（`09-content-sourcing.md` §3） |
| **Wiki用語マスタ／用語リンク** | 用語マスタなしにリンクを張ると誤リンクが記事数に比例して蓄積し、後から直せない | 教材にリンクを張らない。外部導線は動画のみ（`07-content-pipeline.md` §10） |
| **模試画像の取り込み** | 入力種別ごとに実現可能性が全く違う（`04-weakness-engine.md` §6） | 原本を保存しないスキーマを確定（後から変更不可） |
| **過去の教材の全面再生成** | プロンプト改善のたびに全ユーザーの教材を作り直すと RPD が尽きる | 既存教材は残し、新しいプロンプトはこれから生成される分にのみ適用する（`07` §7） |

### 4.3 実装しないと決めたもの

| 機能 | 理由 |
|---|---|
| **論述・記述式の AI 採点** | 対象試験が共通テスト＋私大マークであり、論述は出題されない。AI採点の精度リスクとコストを負う理由がない |
| **他ユーザーとの比較・ランキング** | 非公開・数人での利用であり、母集団が成立しない |
| **チャット形式の質問応答** | ChatGPT の劣化版になる。HISTORIA の価値はそこにない（§2.2） |
| **教材の全文検索** | MVP の教材は400ユニットで、章立てから辿れば足りる。PGroonga の導入は Phase2 の用語検索から |

週15時間（1日2時間 × 平日＋週末）で進めると **約10〜13週間**。
`13-roadmap.md` はこの見積りに基づく。

**最大のコストはコードではなくデータの整備（KCシード12＋正典マスタ4＋診断プール2 = 18人日 = 全体の23%）である。**
カタログ構築（10人日）は消えたが、人手レビューが不可能になった分を
正典マスタと診断プールで埋めることになった。ここを軽く見積もると全体が崩れる。

## 6. 検証すべき最大の仮説

> **AI が生成した教材と問題で、受験世界史の学習が実際に成立するか。**
> 具体的には「HISTORIA で `mastered` になったKCが、実際の入試問題で解けるか」。

これが偽なら、弱点エンジンがどれだけ精緻でも製品として無価値である。

### 6.1 最小コストの検証方法

**カタログを400ユニット作る前に、20ユニットだけで検証する。**

```
1. 共通テスト過去問（世界史探究）1年分を作者が解き、正答率を記録する（事前測定）
2. 落とした設問が属する範囲の 20 ユニットを生成する（**無料枠の RPD を40消費するだけ。費用0円**）
3. 作者が2週間 HISTORIA だけで学習する
4. 別年度の共通テスト過去問を解く（事後測定）
5. HISTORIA 上で mastered になったKCに対応する設問の正答率を測る
```

**判定基準**: `mastered` なKCに対応する設問の正答率が 80% 以上。
下回るなら、`mastered` の閾値か問題の質のどちらかが間違っている。

この検証にかかるのは **2週間と無料枠のRPD 40件だけ**であり、77人日を投じる前に実施できる。
`13-roadmap.md` ではこれを Phase 0 として最初に置く。

### 6.2 その他に検証すること

| 仮説 | 検証方法 | 章 |
|---|---|---|
| AI生成教材に致命的な事実誤りが混入しない | 代表20単元を人手で検算し、年号・人名の誤り件数を数える。**人手レビューが無いため、ここが通らなければ製品が成立しない** | `08-ai-architecture.md` §5 |
| 正典マスタで claim の80%以上を機械照合できる | 20単元の `claims` を `canon_event` に当てて照合率を測る | `08-ai-architecture.md` §5 層2 |
| 未成年向けフィルタが世界史の記述を拒否しない | 十字軍・ホロコースト等10単元でプロンプト検証 | `08-ai-architecture.md` §7.1 |
| 診断テスト24問で離脱しない | 作者と友人3人で実測 | `04-weakness-engine.md` §5 |
| 3,500字の教材をスマホで読み切れる | 読了率とスクロール到達率を計測 | `11-ux.md` |

## 7. 成功の定義

MVP のリリース時点で次を満たしていれば成功とする。

| 指標 | 目標 |
|---|---|
| 作者を含む利用者が2週間継続して使う | 4人中3人 |
| 1日のノルマ達成率 | 60%以上 |
| `mastered` KCの入試問題での正答率（§6.1） | 80%以上 |
| 教材の事実誤りの報告件数 | 400ユニットあたり10件未満 |
| 月額コスト | **0円**（無料枠内。`08-ai-architecture.md` §3） |
| 無料枠の RPD 消費 | 1日あたり 1,500 の 10% 未満 |

**ユーザー数は成功指標にしない。** 非公開・招待制であり、増やすことが目的ではない。
